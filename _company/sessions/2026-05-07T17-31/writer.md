## 🚀 부동산 앱 MVP 개발 및 마케팅 실행 로드맵 초안

본 로드맵은 Business 및 Developer 에이전트의 논의 결과를 기반으로, 핵심 KPI 달성을 위한 MVP 기능 우선순위와 데이터베이스 설계 완료 시점을 연계하여 개발팀에 공식 요청할 수 있는 실행 계획 초안을 제공합니다.

### 1. 목표 및 핵심 연계 (Goal & Core Linkage)

| 구분 | 목표/요소 | 목표 시점 (Target) | 핵심 연계 지점 |
| :--- | :--- | :--- | :--- |
| **비즈니스 목표** | 핵심 KPI 달성 (수익화 가설 검증) | T+3개월 (MVP 출시 시점) | 데이터 범위 및 권한 수준 확정 |

### 2. 단계별 실행 로드맵 (Phase-by-Phase Execution Plan)

#### Phase 1: 요구사항 구체화 및 데이터 정의 (Requirement Definition & Data Definition)
**목표:** MVP에 필요한 데이터 범위와 기술적 요구사항을 최종 확정합니다.
**주요 산출물:** 최종 MVP 기능 목록, 핵심 KPI 연계 테이블, DB 스키마 초안(최종 반영본).
**주요 활동:**
1. **MVP 기능 최종 확정:** 개발팀과 협의하여 가장 핵심적인 기능(Must-Have)과 보조 기능(Nice-to-Have)을 분류합니다.
2. **KPI-DB 매핑:** 각 핵심 KPI(예: 추천 정확도, 사용자 유지율)에 필요한 데이터 필드를 정의하고, 해당 데이터가 DB에서 어떻게 추출될지 정의합니다.
3. **DB 스키마 최종 검토:** Developer가 제시한 DB 스키마 초안을 바탕으로, MVP 기능에 필요한 테이블 구조를 확정하고, 데이터 마이그레이션의 범위와 우선순위를 결정합니다.

**예상 소요 기간:** 1주

#### Phase 2: 데이터 설계 및 권한 확정 (Data Design & Permission Finalization)
**목표:** 데이터 접근 권한(Permission Level)과 기술적 제약 사항을 명확히 하여 개발팀 요청 문서를 준비합니다.
**주요 산출물:** 데이터 접근 요구사항 목록, 기술적 제약사항 명세.
**주요 활동:**
1. **데이터 접근 요청 목록 작성:** Business가 정의한 KPI 달성을 위해 필요한 데이터 소스(Scope)와 최소한의 권한 수준(Permission Level)을 구체적으로 목록화합니다. (Developer의 기술적 검토 결과를 반영)
2. **기술적 제약사항 정의:** DB 설계 및 API 연동 과정에서 발생할 수 있는 기술적 난점(예: 데이터 정합성, 실시간성)을 명시합니다.
3. **데이터 마이그레이션 계획 초안:** 정의된 DB 스키마를 기반으로 데이터 마이그레이션의 단계별 계획(Stage-wise plan)을 초안 작성합니다.

**예상 소요 기간:** 1주

#### Phase 3: 개발 착수 및 콘텐츠 연계 (Development Kick-off & Content Sync)
**목표:** 명확한 로드맵을 기반으로 개발을 시작하고, 콘텐츠 제작을 동시 진행하여 시너지를 극대화합니다.
**주요 산출물:** 개발팀 공식 요청 문서(Final Request Document), 콘텐츠 제작 마일스톤.
**주요 활동:**
1. **공식 요청 문서 준비:** Phase 2에서 정리된 모든 요구사항(MVP, DB, 접근 권한)을 포함하여 개발팀에 전달할 최종 요청 문서를 작성하고 공식 제출합니다.
2. **개발 착수:** 개발팀이 공식 요청 문서를 기반으로 MVP 개발을 시작합니다.
3. **콘텐츠 제작 동시 진행:** 개발 진척도에 맞춰, Writer가 준비한 영상 스크립트 및 후킹 문구를 활용하여 개발 진행 상황을 반영한 콘텐츠(예: 개발 과정 비하인드 영상)를 제작하여 마케팅에 활용합니다.

**예상 소요 기간:** 4주 (개발 시작 시점 기준)
