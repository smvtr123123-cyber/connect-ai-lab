## 부동산 추천 앱 MVP: 데이터 범위 및 권한 최종 확정 및 기술 요구사항 정리

본 문서는 부동산 추천 앱 MVP의 핵심 KPI 달성을 위해 필요한 데이터 범위(Scope)와 권한 수준을 최종 확정하고, 이를 기반으로 개발팀에 전달할 기술적 요구사항의 핵심 논점을 정리합니다.

### 1. 핵심 KPI 기반 데이터 범위(Scope) 정의

MVP의 핵심 목표는 **"부동산 추천을 통한 사용자 만족도 증대 및 잠재적 수익화 기반 마련"**입니다. 이를 달성하기 위해 필요한 데이터 범위는 최소화하되, 추천 알고리즘의 정확도와 사용자 경험을 보장하는 데 필수적인 데이터에 한정합니다.

| MVP 기능 목표 | 필수 데이터 범위 (Scope) | 상세 데이터 항목 (예시) | 비고 (KPI 연계) |
| :--- | :--- | :--- | :--- |
| **지역 기반 추천** | 지역별 기본 정보 (필수) | 시/도, 구/군, 동, 평균 시세 데이터 | 지역별 경쟁 우위 분석 |
| **부동산 상세 정보** | 매물 기본 정보 | 주소, 면적(평수), 층수, 방/채 수, 거래 시점 | 추천 정확도 및 사용자 만족도 |
| **시장 동향 반영** | 시세 및 거래 데이터 | 최근 3개월/6개월 평균 거래가, 매물 수 | 시장 분석 기능 제공 |
| **사용자 피드백** | 사용자 리뷰/평점 | 사용자 리뷰 텍스트, 평점 점수 | 서비스 신뢰도 및 재방문율 |

**결론:** MVP 단계에서는 **'정확한 지역별 시세 데이터'**와 **'매물 기본 정보'**에 집중해야 하며, 민감하거나 비공개적인 상세 거래 정보는 초기 단계에서는 제외하여 데이터 요청의 복잡성과 보안 리스크를 최소화합니다.

### 2. 권한 수준(Permission Level) 최종 확정

데이터 접근 권한은 **'최소 권한의 원칙(Principle of Least Privilege)'**에 따라 정의하여 개발 효율성과 보안을 동시에 확보합니다.

*   **데이터 접근 수준:** **읽기 전용 (Read-Only)** 접근만을 허용합니다. (쓰기/수정 권한은 MVP 이후 단계에서 별도 승인 필요)
*   **데이터 범위:** **지역 코드 기반**으로 데이터 요청을 설계합니다. (DB 스키마 설계에 따라 지역 코드를 기준으로 데이터 접근을 제한)
*   **보안 고려사항:** 모든 데이터 요청은 API 게이트웨이를 통해 이루어지며, 데이터 요청 시에는 **KPI 달성에 직접적으로 기여하는 최소한의 필드만** 요청하도록 제한합니다.

### 3. 개발팀 전달을 위한 핵심 논점 (Key Discussion Points)

개발팀이 이 요구사항을 이해하고 효율적으로 개발 로드맵을 수립할 수 있도록 다음 논점을 강조합니다.

1.  **KPI 연계성 강조:** "우리의 데이터 요청은 단순한 정보 수집이 아니라, **핵심 KPI(예: 추천 정확도, 사용자 참여율) 달성**을 위한 필수적인 입력값임을 명확히 인지해야 합니다."
2.  **데이터 범위의 명확화:** "MVP 단계에서는 **지역 코드, 면적, 기본 가격** 등 핵심 필드에 대한 접근을 우선적으로 요구하며, 상세 거래 기록과 같은 민감 데이터는 추후 단계에서 추가 논의를 통해 접근 권한을 확대할 계획입니다."
3.  **기술적 제약 사항의 반영:** "데이터 요청의 효율성과 개발 일정 연계성을 극대화하기 위해, 요청되는 데이터 범위가 **DB 스키마 및 API 설계의 제약 조건** 내에서 최적화되어야 합니다. 데이터 요청의 효율성을 기술적 요구사항의 일부로 간주하고 논의합시다."
