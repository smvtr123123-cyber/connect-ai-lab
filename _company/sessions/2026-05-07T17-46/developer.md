## 부동산 추천 앱 MVP 데이터베이스 스키마 및 기술 실현 가능성 검토 보고서

Business 에이전트가 제안한 데이터 범위 및 권한 수준을 바탕으로, 부동산 추천 앱 MVP에 필요한 데이터베이스 스키마 초안을 검토하고 기술적 실현 가능성(DB, API, 보안)에 대한 제약 사항을 다음과 같이 정리합니다.

### 1. 데이터베이스 스키마 (DB Schema) 초안 검토

**검토 결과:** 제안된 데이터 범위(지역 코드, 매물 기본 정보, 시세 데이터, 사용자 피드백)는 MVP 목표(지역 기반 추천 및 기본 정보 제공)를 달성하기에 **충분하며 논리적**입니다. 핵심은 데이터 간의 관계 설정과 지역 코드 기반의 접근 제어에 있습니다.

| 테이블/엔티티 | 핵심 필드 | 관계 및 검토 사항 | 기술적 실현 가능성 |
| :--- | :--- | :--- | :--- |
| **Regions (지역)** | `region_id` (PK), `city`, `province`, `district`, `region_code` (FK) | 모든 데이터의 최상위 식별자로 사용됨. 지역 코드 기반 접근 제어의 핵심. | **높음** (정규화 용이) |
| **Properties (매물)** | `property_id` (PK), `region_id` (FK), `address`, `area_sqm`, `floor`, `room_count`, `listing_date` | 지역과 1:N 관계. 추천 알고리즘의 핵심 입력값. | **높음** (표준화된 GIS/주소 API 연동 필요) |
| **MarketData (시장 데이터)** | `market_id` (PK), `region_id` (FK), `avg_price_3m`, `avg_price_6m`, `listing_count` | 지역별 시장 동향 제공. 추천 정확도에 직접 기여. | **중간** (외부 시세 API 연동 및 데이터 정제 필요) |
| **Reviews (사용자 피드백)** | `review_id` (PK), `property_id` (FK), `user_id` (FK), `rating`, `comment` | 사용자 만족도 측정. 추천 알고리즘의 보조 입력값. | **높음** (관계 설정 용이) |

### 2. API 및 데이터 파이프라인 제약 사항

**제약 사항:**

1.  **지역 코드 기반 접근 제어 (Security & API):**
    *   **제약:** 모든 API 엔드포인트는 반드시 `region_code`를 파라미터로 요구해야 하며, 이 코드가 데이터베이스 접근의 **최우선 보안 필터**로 작동해야 합니다.
    *   **실현 방안:** API 게이트웨이 레벨에서 사용자 인증 정보와 요청된 `region_code`를 매칭하여, 해당 코드가 허용된 범위 내에 있는지 실시간으로 검증해야 합니다.
2.  **데이터 동기화 (Data Pipeline):**
    *   **제약:** `MarketData` 테이블은 실시간성이 중요하므로, 외부 부동산 API 또는 크롤링 시스템과의 **안정적인 데이터 파이프라인** 구축이 선행되어야 합니다. 수동 업데이트는 금지합니다.
    *   **실현 방안:** 외부 소스(예: 공공 데이터 포털, 상업용 부동산 API)에서 데이터를 가져와 ETL(Extract, Transform, Load) 프로세스를 통해 DB에 정기적으로 반영하는 자동화 스크립트(Python/Airflow)를 구축해야 합니다.
3.  **데이터 범위 제한 (Scope Limitation):**
    *   **제약:** MVP 단계에서는 민감한 개인 거래 정보(실제 매매 가격, 개인 연락처 등)는 **DB에 저장하지 않거나, 암호화하여 별도의 보안 레이어**에 분리해야 합니다. 저장되는 데이터는 **추천 알고리즘에 필요한 집계된 통계 데이터**로 제한해야 합니다.

### 3. 기술적 실현 가능성 요약

| 영역 | 실현 가능성 | 핵심 제약 사항 |
| :--- | :--- | :--- |
| **DB 설계** | 높음 | 지역 코드(Region Code)를 PK/FK의 핵심으로 설정하여 데이터 격리 및 접근 통제를 용이하게 함. |
| **API 통합** | 중간 | 외부 시세 데이터의 안정적인 확보 및 실시간 업데이트를 위한 외부 API 의존성이 높음. |
| **보안** | 높음 | 최소 권한 원칙을 DB 접근 및 API 응답에 강력하게 적용할 경우, 데이터 유출 위험을 최소화할 수 있음. |
